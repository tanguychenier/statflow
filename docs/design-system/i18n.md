## 1. Configuration

### 1.1 vue-i18n Setup

```typescript
// src/i18n/index.ts
import { createI18n } from 'vue-i18n'
import type { I18nOptions } from 'vue-i18n'
import en from './locales/en.json'
import fr from './locales/fr.json'

export type SupportedLocale = 'en' | 'fr'

const options: I18nOptions = {
  legacy: false,              // Composition API mode
  locale: detectLocale(),     // See section 2
  fallbackLocale: 'en',
  messages: { en, fr },
  datetimeFormats: {
    en: datetimeFormatsEn,
    fr: datetimeFormatsFr,
  },
  numberFormats: {
    en: numberFormatsEn,
    fr: numberFormatsFr,
  },
  missingWarn: import.meta.env.DEV,
  fallbackWarn: import.meta.env.DEV,
}

export const i18n = createI18n(options)
```

### 1.2 Locale Detection Order

```typescript
// src/i18n/detectLocale.ts
export function detectLocale(): SupportedLocale {
  // 1. User's explicit preference (stored in Pinia + localStorage)
  const stored = localStorage.getItem('sf-locale')
  if (stored === 'en' || stored === 'fr') return stored

  // 2. Browser navigator.language
  const browserLang = navigator.language.split('-')[0]
  if (browserLang === 'fr') return 'fr'

  // 3. Fallback
  return 'en'
}
```

### 1.3 Locale Switching

Switching locale is instant — no page reload. The composable updates both the vue-i18n instance and `localStorage`.

```typescript
// src/composables/useLocale.ts
import { useI18n } from 'vue-i18n'
import type { SupportedLocale } from '@/i18n'

export function useLocale() {
  const { locale } = useI18n()

  function setLocale(newLocale: SupportedLocale) {
    locale.value = newLocale
    localStorage.setItem('sf-locale', newLocale)
    document.documentElement.lang = newLocale
    document.documentElement.dir = 'ltr' // both EN and FR are LTR
  }

  return { locale, setLocale }
}
```

## 3. Date & Time Formatting

All date/time formatting goes through `vue-i18n`'s `d()` function (backed by `Intl.DateTimeFormat`). No manual date formatting is permitted in components.

### 3.2 Relative Time Formatting

Used for "Updated 2 minutes ago" (Realtime screen) and "Joined 3 months ago" (Team settings).

```typescript
// src/composables/useRelativeTime.ts
import { computed } from 'vue'
import { useI18n } from 'vue-i18n'

export function useRelativeTime() {
  const { locale } = useI18n()

  function format(date: Date): string {
    const rtf = new Intl.RelativeTimeFormat(locale.value, { numeric: 'auto' })
    const diffMs = date.getTime() - Date.now()
    const diffSec = Math.round(diffMs / 1000)
    const diffMin = Math.round(diffSec / 60)
    const diffHour = Math.round(diffMin / 60)
    const diffDay = Math.round(diffHour / 24)
    const diffMonth = Math.round(diffDay / 30)
    const diffYear = Math.round(diffDay / 365)

    if (Math.abs(diffSec) < 60)  return rtf.format(diffSec, 'second')
    if (Math.abs(diffMin) < 60)  return rtf.format(diffMin, 'minute')
    if (Math.abs(diffHour) < 24) return rtf.format(diffHour, 'hour')
    if (Math.abs(diffDay) < 30)  return rtf.format(diffDay, 'day')
    if (Math.abs(diffMonth) < 12) return rtf.format(diffMonth, 'month')
    return rtf.format(diffYear, 'year')
  }

  return { format }
}
```

Output examples:

- EN: "2 minutes ago", "yesterday", "3 months ago"
- FR: "il y a 2 minutes", "hier", "il y a 3 mois"

### 4.2 Duration Formatting

Session durations (e.g. "2m 04s") use a custom utility (not vue-i18n, since there is no standard `Intl` API for duration):

```typescript
// src/utils/formatDuration.ts
export function formatDuration(seconds: number, locale: string): string {
  const m = Math.floor(seconds / 60)
  const s = seconds % 60
  if (locale === 'fr') {
    if (m === 0) return `${s}s`
    return `${m}m ${String(s).padStart(2, '0')}s`
  }
  if (m === 0) return `${s}s`
  return `${m}m ${String(s).padStart(2, '0')}s`
}
// Output: "2m 04s" (same in both locales — universally understood)
```

## 5. Pluralization

vue-i18n supports ICU-style plurals via the pipe syntax:

```json
{
  "sessions": "{count} session | {count} sessions",
  "users": "{count} utilisateur | {count} utilisateurs"
}
```

Usage in components:

```typescript
const { t, n } = useI18n()
// t('common.sessions', { count: 1 })   → "1 session"
// t('common.sessions', { count: 142 }) → "142 sessions"
```

French has different pluralization rules (e.g. "0 session" in French uses the singular, unlike English "0 sessions"). vue-i18n handles this correctly with the standard `{ count }` pluralization.

## 6. Text Direction & Typography

Both EN and FR are left-to-right. The `dir="ltr"` attribute is set on `<html>`. No RTL support is required in v1.0, but the layout must not hard-code directional assumptions (use `margin-inline-start` not `margin-left`, `padding-inline` not `padding-left/right`, etc.) so that RTL can be added later without a full layout rewrite.

## 7. Chart Axis Labels

ECharts axis labels are generated from data arrays, not from vue-i18n directly. The chart composable receives the active locale and formats all axis values:

```typescript
// inside useChart.ts
import { useI18n } from 'vue-i18n'

const { locale, n, d } = useI18n()

// Format date axis labels
function formatAxisDate(date: Date): string {
  return d(date, 'monthShort')
  // EN: "Dec 15", FR: "15 déc."
}

// Format value axis labels
function formatAxisValue(value: number): string {
  return n(value, 'compact')
  // EN: "12.0K", FR: "12 k"
}
```

## 8. i18n Quality Assurance

### 8.1 Missing Key Detection

In development mode (`import.meta.env.DEV`), vue-i18n logs a console warning for any missing translation key. The CI pipeline includes a script that compares `en.json` and `fr.json` key counts and fails if they diverge.

### 8.2 Translation Workflow

1. EN is the source of truth — all new strings are added to `en.json` first
2. A `TODO` comment is added to `fr.json` where the key is missing
3. Translations are reviewed by a native speaker before merging into `main`
4. Machine-translated strings are acceptable as a placeholder but flagged with `// MACHINE` in a comment (not in the JSON itself — in a separate `fr.todo.json` tracking file)

### 8.3 Translation Key Rules

- Keys are **camelCase** within each namespace
- Namespaces are **camelCase** nouns (not verbs)
- No nesting deeper than **3 levels** (`namespace.section.key`)
- Interpolated variables use `{camelCaseName}` syntax
- ICU plural forms use the pipe `|` syntax
- Keys never contain HTML (use the `i18n-t` component for embedded links/formatting)

### 8.4 i18n-t for Rich Text

When a translation needs inline HTML elements (e.g. a link inside a sentence):

```html
<!-- EN: "I agree to the Terms of Service and Privacy Policy" -->
<i18n-t keypath="auth.register.terms" tag="label">
  <template #terms>
    <a href="/terms" target="_blank">{{ t('auth.register.termsLink') }}</a>
  </template>
  <template #privacy>
    <a href="/privacy" target="_blank">{{ t('auth.register.privacyLink') }}</a>
  </template>
</i18n-t>
```

This approach avoids `v-html` directives entirely.
